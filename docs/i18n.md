# Translations (i18n)

The app is available in **English (en), Croatian (hr), German (de) and Arabic (ar)**.

- Texts live in `src/i18n/locales/<language>.json`. Every screen reads them with `t('some.key')` from `useTranslation()`.
  Code outside React components (validation, constants, services) uses `i18n.t(...)` from `src/i18n`.
- English is the fallback language. A missing key in another language shows the English text and prints
  `[i18n] Missing translation key` in the development console.
- The language is chosen in **Profile > Settings > Language** and saved in `user_profile.locale`
  (`src/i18n/locale.ts`). On the first launch the phone's language is used when it is supported.
- Plurals use i18next suffixes: English and German `_one/_other`, Croatian `_one/_few/_other`,
  Arabic `_zero/_one/_two/_few/_many/_other`.
- Dates, times and numbers are formatted with `Intl` through `src/i18n/format.ts`.
- Preset situations (for example "Small talk") are stored in the language that was active when they were chosen.
  Event types, moods and recharge ideas are stored as keys and are translated when shown.

## Arabic and right-to-left layout

`src/i18n/index.ts` calls `I18nManager.allowRTL(true)` and `forceRTL(true)` for Arabic. React Native only applies a new
layout direction after a restart, so Settings shows a "Restart needed" message when the direction changes.
Components use `marginStart/marginEnd` instead of left/right, back arrows flip with `I18nManager.isRTL`, and the
battery icon and the time chart are always drawn left to right on purpose.

## Adding a new text

1. Add the key to all four files in `src/i18n/locales`.
2. Use `t('your.key')` in the component. Do not write text directly in JSX (ESLint blocks it).
